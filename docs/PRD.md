# CourseScribe 需求文档

> 需求变了先改这份文档，再改测试和代码。

## 一句话

看网课时一键录下电脑播放的声音，或者选一个本地音视频文件，自动得到原始文字稿（`.txt`）和校对后的完整文字稿（`.md`）。校对后的文字稿保留原文，不是总结。

## 每天怎么用

### 看网课

1. 打开 CourseScribe，点“开始”或按全局快捷键。
2. 正常看课，声音照常外放。
3. 看完点“停止”或再按一次快捷键，可以直接离开。
4. 回来时，文件夹里已经有录音、`.txt` 和 `.md`。

### 已有音视频文件

1. 把文件拖进小窗口，或点“选择文件”，可以一次选多个。
2. 文件按顺序自动处理，不用播放，也不用录音。

## 第一版要做的

### 录音

- 只录电脑播放的声音，不录麦克风。
- Windows 和 Mac 都不需要用户改声音设置，也不需要安装虚拟声卡。Mac 只需首次授权。
- 录音边录边写入磁盘。程序崩溃或被强制关闭，最多丢失最后几秒。
- 录到持续无声时要提醒用户，避免录完才发现是空的。
- 录音中声音设备断开或电脑睡眠后醒来，自动重新连接，接着录进同一个文件；连不上就自动停止，并照常转录已录下的部分。
- 录音中换了默认的输出设备（插上耳机、在系统里换了扬声器），即使原来的设备还在，也会在 1–2 秒内跟着换到新设备，接着录进同一个文件，窗口说明换到了哪个设备；换的那一下可能漏掉约 1 秒，用静音补上，录音时长和实际时间一致。新设备打不开（比如被别的程序独占）时继续录原来的设备，窗口提醒可能录不到声音和怎么办，并每隔几秒自动再试。
- 一个录音文件最长约 6 小时（WAV 格式上限）。到上限时自动停止并转录，窗口说明原因。
- 录音和处理期间不让电脑自动睡眠。合上笔记本盖子等主动睡眠不受影响。

### 本地文件

- 支持常见音视频格式，至少包括 mp3、wav、m4a、mp4、mkv。
- 可以一次选择或拖入多个文件，按顺序处理。
- 只读取原文件，不修改、不移动、不删除。

### 转录和校对

- 录音和本地文件走同一条处理流程：转录 → 写 `.txt` → 校对 → 写 `.md`。
- 校对内容：错别字和同音字、标点、断句、分段。目标是贴近 Jeremy 人工定稿的“清稿”，让他基本不用再改。
- `.md` 可以删除的只有三类：语气词（嗯、呃、啊、呢、哈、呀）；口头禅（对吧、对不对、对啊、yeah、作停顿用的“这个”“那个”“然后呢”）；紧挨着的口吃式重复（只留一遍）。指代 AI、软件、工具时用“它”。除此之外不总结、不改写、不增加内容。
- `.md` 第一行是任务名作标题（`# 名称`），不加其他标题和要点。段落按话题分，一段通常几句话，不要整页一段。
- 词表：用户可以在设置里打开一个文本文件，写常用词和“听错 → 正确”的替换（如“见行 → 践行”）。替换在校对前自动完成，常用词也交给校对模型参考。词表存成 UTF-8（带不带 BOM 都行）、带 BOM 的 UTF-16，或中文 Windows 记事本的“ANSI”（GBK）都能读，在哪台电脑上都一样。替换在去掉语气词、把分行接起来之后的文字里找，所以被换行或“嗯”隔开的词也能换。英文替换只替换完整的词（汉字、空格和标点都算词的边界，`-` 和 `_` 不算），区分大小写，不改到别的词里面；同一处只替换一次，替换上去的词不会再被替换。程序内置的几个英文术语（如 Claude、ChatGPT、GitHub、Python）总按内置写法拼写，词表里把它们换成别的大小写不起作用。
- `.txt` 保留全部转录内容，任何校对步骤都不能改它。
- 模型漏字时必须被检测到：删掉的内容不属于上面三类、又超过两个字，就算漏字。这一段重试，仍不合格就用只按规则清理过的文字，并告诉用户有几段没校对。模型的回答写到长度上限被截断的，同样算这一段不合格，不当作完整的回答。
- 网课内容以中文夹英文术语为主，英文术语要尽量保持英文原文。

### 窗口和设置

- 一个小窗口，主界面只有开始/停止、选择文件和当前进度。
- 默认设置开箱即用，日常使用不用选模型或参数。
- 设置里可以手动切换转录模型和校对模型，也可以修改保存文件夹。
- 进度和错误用普通话术显示，比如“正在校对（第 3/20 段）”。

### 失败时

- 程序被关闭后重新打开，自动继续没做完的任务，不会重复处理已完成的部分。
- 校对服务（Ollama）没启动或缺模型时，`.txt` 照常生成，任务显示“等待校对”并说明怎么解决；问题解决后点一下即可继续。
- 程序不会把未校对的文字稿存成 `.md` 冒充校对结果。
- 不覆盖任何已有文件，重名时自动加序号。
- 出错时窗口必须说清原因和怎么办，不能点了没反应。
- 处理出错的任务可以点“重试”，从出错的那一步继续；不需要的点“忽略”。
- 同一个任务连续两次让程序意外退出，就暂停它，不再在启动时自动继续，避免每次打开都崩溃；用户可以手动重试。
- 校对服务临时出错（超时、显存不够）时，任务显示“等待校对”，可以重做这些段落，不当作永久失败。
- 录音文件被别的程序占用、被移走或修复时写不进磁盘，窗口说明是哪个文件、怎么办，并可以重试；不当成空录音。
- 显卡这次用不了（比如显存被别的程序占满）时改用处理器转录，状态里说明会慢一些，下一个任务会再试显卡；转录模型怎么都启动不了时，说明原因并可以重试。
- 词表读不了（编码认不出、被占用）时不带着读错的词表校对：说明是哪个文件、怎么办，文字稿保留，改好后可以重试。没有词表文件时照常校对。

## 文件存放

默认保存到系统“文档”下的 `CourseScribe` 文件夹，每个任务一个子文件夹：

```text
文档/CourseScribe/
└── 2026-11-01 19-30 录音/
    ├── 2026-11-01 19-30 录音.wav
    ├── 2026-11-01 19-30 录音.txt
    └── 2026-11-01 19-30 录音.md
```

本地文件的任务文件夹用原文件名命名，不复制原文件。原文件名太长时截短（最多 80 个字符，保存文件夹路径很长时更短），避免超过 Windows 的路径长度限制；名字末尾的空格和点会去掉，去完为空时叫“未命名”。保存文件夹本身的路径太长、放不下任何名字时，不开始录音、不加入文件，并提示换一个路径短一些的文件夹。

“文档”文件夹被 OneDrive 或 iCloud 同步时，默认改存到用户主文件夹下的 `CourseScribe`，因为音频和文稿不能被自动上传。用户在设置里自己选的文件夹不受影响。

## 整理笔记（可选）

把一节课的校对稿整理成一份复习用的学习笔记，结构和用户在 Obsidian 里的整理笔记一致：核心宗旨、本课脉络、按讲课顺序分节、案例、类比、引述、提示词、结尾总结。

- 只在用户选择时生成。三种方式：任务完成后点“生成整理笔记”；把已有的 `.md` 拖进窗口或选中它；在设置里勾选“转录完自动生成整理笔记”（默认不勾）。
- 结果单独存成 `名称-整理笔记.md`，放在校对稿旁边。不修改 `.txt` 和 `.md`，不覆盖已有文件。
- 整理规则是一个文本文件，在设置里打开，用户可以改。程序自带一份通用规则。
- 模型可以在设置里单独选，默认 `qwen3.5:9b`。和校对一样只用本机 Ollama。
- 程序负责以下各项，不依赖模型：
  - 开头信息（标题、日期、来源链接）由程序写。
  - 本课脉络的链接由程序按实际小节生成。
  - 引述和原文逐字核对，对不上的删掉。
  - 概念标签只保留原文里出现过的。
  - 完成后告诉用户删掉了几条。
- 笔记是模型写的初稿，可能遗漏或概括不准，需要用户自己看一遍。
- 细节：
  - “生成整理笔记”按钮针对最近完成的一个任务；更早的课把它的校对稿 `.md` 拖进来或选中。拖入 `.txt` 或 `*-整理笔记.md` 时说明不能用。
  - 日期取名称里的日期（如 `2026.10.30`、`2026-11-01`），没有就用任务建立的日期；不用“今天”，这样重做时内容不变。来源链接指向校对稿（`[[名称]]`），另留一行空的“来源：”给用户填课程地址；不写本机路径。
  - 本课脉络用 Obsidian 的 `[[#小节]]` 链接。
  - 引述只认引述小节里的 `>` 行或引号里的话，去掉结尾的“——某某”后，只比文字和数字（不比标点、空格、大小写）；带“……”的每一段都要按顺序在原文里；少于 4 个字的删掉（太短，核对不了）。概念标签是 `#标签`。
  - 同一份校对稿正在整理时再点一次不重复整理，提示“已经在整理了”；整理完再点，新存一份 `名称-整理笔记 (2).md`。
  - 课太长、一次放不进模型时，调用模型前就停下，说明有多长、上限多少；不悄悄截断。拆成几段整理以后再做。
  - 模型的回答写到长度上限被截断时，不保存半截的笔记，算这次整理失败并说明。
  - 笔记模型没装时提示运行 `ollama pull 模型名` 或在设置里换成已有的模型；程序不自己下载。
  - 自动生成在校对稿写好后开始；校对在等待时笔记跟着等。
  - 笔记和转录、校对排同一个队，同一时间只占一个模型；笔记失败不影响已经完成的 `.txt` 和 `.md`，可以重试或忽略。

## 硬规则

- **隐私：** 音频和文稿不离开本机。只有下载模型时联网，程序运行时不上传任何内容，也没有使用统计。
- **模型下载：** 程序不会静默下载大模型，下载前必须说明大小并得到同意。
- **平台：** Windows 和 Mac（Apple 芯片）都是正式平台。系统相关代码必须隔离，其他代码不能直接判断操作系统。
- **公开：** 以后会公开。仓库内容始终按公开标准管理：不放密钥、本机路径、私人录音或讲课内容。测试素材必须是自己生成或有权公开的。
- **路径：** 程序默认位置来自系统目录，不写死任何人的电脑路径。

## 怎样算做完

Jeremy 亲手验收，全部通过才算第一版完成：

1. 点开始、看课、点停止，全程不用再点别的，也不用选模型或参数。
2. 录音时电脑正常外放，不用改声音设置，Mac 只需首次授权。
3. 一节 1 小时的课，停止后自动生成 `.txt` 和 `.md`，无需人工盯着。
4. `.md` 能直接阅读，内容没有被总结或删减（语气词、口头禅和重复除外），最多只需修个别错字。
5. 强制关闭程序后，录音还在，并能继续完成转录。
6. 选择或拖入一个本地音视频文件后，无需其他操作，自动生成 `.txt` 和 `.md`。
7. 设置里能切换转录模型和校对模型，切换后下一个任务生效。

以上在 Windows 和 Mac 上都要通过。

## 给别人用的方式

- 公开时提供 Windows 和 Mac 安装包，同时公开源码。
- 安装包不做付费签名，Mac 用户首次打开需要手动放行。
- 模型不打进安装包，首次使用时提示下载。
- 校对依赖用户自己安装 Ollama，安装引导放到公开前的阶段做。

## 第一版不做

- 边录边显示文字。
- 录麦克风。
- 把总结、要点写进 `.md`，课后作业（旧项目的“深度排版”）。可选的整理笔记见上文，单独成文件。
- 云端转录或云端校对。
- 专门的词表编辑界面（第一版用文本文件编辑词表）。
- 正式发布和自动更新（第一版只演练打包，不公开发布）。
