# CourseScribe 需求文档

> 需求变了先改这份文档，再改测试和代码。

## 一句话

看网课时一键录下电脑播放的声音，或者选一个本地音视频文件，自动得到原始文字稿（`.txt`）和校对后的完整文字稿（`.md`）。校对后的文字稿保留原文，不是总结。

## 每天怎么用

### 看网课

1. 打开 CourseScribe，点“开始”或按全局快捷键。
2. 正常看课，声音照常外放。
3. 看完点“停止”或再按一次快捷键，可以直接离开。
4. 回来时，文件夹里已经有录音、`.txt` 和 `.md`。

### 已有音视频文件

1. 把文件拖进小窗口，或点“选择文件”，可以一次选多个。
2. 文件按顺序自动处理，不用播放，也不用录音。

## 第一版要做的

### 录音

- 只录电脑播放的声音，不录麦克风。
- Windows 和 Mac 都不需要用户改声音设置，也不需要安装虚拟声卡。Mac 只需首次授权。
- 录音边录边写入磁盘。程序崩溃或被强制关闭，最多丢失最后几秒。
- 录到持续无声时要提醒用户，避免录完才发现是空的。
- 录音中声音设备断开或电脑睡眠后醒来，自动重新连接，接着录进同一个文件；连不上就自动停止，并照常转录已录下的部分。
- 录音中换了默认的输出设备（插上耳机、在系统里换了扬声器），即使原来的设备还在，也会在 1–2 秒内跟着换到新设备，接着录进同一个文件，窗口说明换到了哪个设备；换的那一下可能漏掉约 1 秒，用静音补上，录音时长和实际时间一致。新设备打不开（比如被别的程序独占）时继续录原来的设备，窗口提醒可能录不到声音和怎么办，并每隔几秒自动再试。
- 一个录音文件最长约 6 小时（WAV 格式上限）。到上限时自动停止并转录，窗口说明原因。
- 录音和处理期间不让电脑自动睡眠。合上笔记本盖子等主动睡眠不受影响。

### 本地文件

- 支持常见音视频格式，至少包括 mp3、wav、m4a、mp4、mkv。
- 可以一次选择或拖入多个文件，按顺序处理。
- 只读取原文件，不修改、不移动、不删除。

### 转录和校对

- 录音和本地文件走同一条处理流程：转录 → 写 `.txt` → 校对 → 写 `.md`。
- 校对内容：错别字和同音字、标点、断句、分段。目标是贴近 Jeremy 人工定稿的“清稿”，让他基本不用再改。
- `.md` 可以删除的只有三类：语气词（嗯、呃、啊、呢、哈、呀）；口头禅（对吧、对不对、对啊、yeah、作停顿用的“这个”“那个”“然后呢”）；紧挨着的口吃式重复（只留一遍）。指代 AI、软件、工具时用“它”。除此之外不总结、不改写、不增加内容。
- `.md` 第一行是任务名作标题（`# 名称`），不加其他标题和要点。段落按话题分，一段通常几句话，不要整页一段。
- 词表：用户可以在设置里打开一个文本文件，写常用词和“听错 → 正确”的替换（如“见行 → 践行”）。替换在校对前自动完成，常用词也交给校对模型参考。词表存成 UTF-8（带不带 BOM 都行）、带 BOM 的 UTF-16，或中文 Windows 记事本的“ANSI”（GBK）都能读，在哪台电脑上都一样。替换在去掉语气词、把分行接起来之后的文字里找，所以被换行或“嗯”隔开的词也能换。英文替换只替换完整的词（汉字、空格和标点都算词的边界，`-` 和 `_` 不算），区分大小写，不改到别的词里面；同一处只替换一次，替换上去的词不会再被替换。程序内置的几个英文术语（如 Claude、ChatGPT、GitHub、Python）总按内置写法拼写，词表里把它们换成别的大小写不起作用。
- `.txt` 保留全部转录内容，任何校对步骤都不能改它。
- 模型漏字时必须被检测到：删掉的内容不属于上面三类、又超过两个字，就算漏字。这一段重试，仍不合格就用只按规则清理过的文字，并告诉用户有几段没校对。模型的回答写到长度上限被截断的，同样算这一段不合格，不当作完整的回答。
- 网课内容以中文夹英文术语为主，英文术语要尽量保持英文原文。

### 窗口和设置

- 一个小窗口，主界面只有开始/停止、选择文件和当前进度。
- 默认设置开箱即用，日常使用不用选模型或参数。
- 设置里可以手动切换转录模型和校对模型，也可以修改保存文件夹。
- 设置保存不了（磁盘满、没有权限）时，窗口说明原因；这次打开期间按新设置做，下次打开程序时还是上次保存的设置。升级以后，旧版本保存的设置照常使用；设置文件里笔记模型或自动生成这一项写坏了，只有这一项回到默认，其他设置不变。笔记模型一栏清空后保存，就回到默认的 `qwen3.5:9b`。
- 录音快捷键可以在设置里改（默认 Windows 是 Ctrl+Alt+R，Mac 是 ⌃⌥R）。在设置里点“录音快捷键”一栏，直接按下想要的组合键就录入，旁边有“恢复默认”。规则：必须带 Ctrl、Alt 或 Mac 的 Command 里的至少一个（只有 Shift 或不带修饰键会误触，不允许）；主键只能是字母、数字或 F1–F12；Windows 上不允许 Win 键。不合规的组合当场说明原因，不保存。和快捷键不同，这一项点“保存”后立刻生效，不用等下一个任务。新组合被别的程序占用时，说明原因，继续用原来的组合（原来的也注册不上就明说现在没有快捷键，按钮照常能用）。设置文件里这一项写坏了（不认识的组合、不合规），只有这一项回到默认。主窗口下方的提示跟着显示当前的组合。
- 进度和错误用普通话术显示，比如“正在校对（第 3/20 段）”。

### 失败时

- 程序被关闭后重新打开，自动继续没做完的任务，不会重复处理已完成的部分。
- 校对服务（Ollama）没启动或缺模型时，`.txt` 照常生成，任务显示“等待校对”并说明怎么解决；问题解决后点一下即可继续。
- 程序不会把未校对的文字稿存成 `.md` 冒充校对结果。
- 不覆盖任何已有文件，重名时自动加序号。
- 出错时窗口必须说清原因和怎么办，不能点了没反应。
- 处理出错的任务可以点“重试”，从出错的那一步继续；不需要的点“忽略”。
- 同一个任务连续两次让程序意外退出，就暂停它，不再在启动时自动继续，避免每次打开都崩溃；用户可以手动重试。
- 校对服务临时出错（超时、显存不够）时，任务显示“等待校对”，可以重做这些段落，不当作永久失败。
- 录音文件被别的程序占用、被移走或修复时写不进磁盘，窗口说明是哪个文件、怎么办，并可以重试；不当成空录音。
- 显卡这次用不了（比如显存被别的程序占满）时改用处理器转录，状态里说明会慢一些，下一个任务会再试显卡；转录模型怎么都启动不了时，说明原因并可以重试。
- 词表读不了（编码认不出、被占用）时不带着读错的词表校对：说明是哪个文件、怎么办，文字稿保留，改好后可以重试。没有词表文件时照常校对。

## 文件存放

默认保存到系统“文档”下的 `CourseScribe` 文件夹，每个任务一个子文件夹：

```text
文档/CourseScribe/
└── 2026-11-01 19-30 录音/
    ├── 2026-11-01 19-30 录音.wav
    ├── 2026-11-01 19-30 录音.txt
    └── 2026-11-01 19-30 录音.md
```

本地文件的任务文件夹用原文件名命名，不复制原文件。原文件名太长时截短（最多 80 个字符，保存文件夹路径很长时更短），避免超过系统的长度限制：Windows 看整条路径（259 个字符）；Mac 看每个文件名（255 字节，一个汉字占 3 字节）和整条路径（1023 字节），截断时给后面的“ (99)”和“-整理笔记 (99).md”留出位置；名字末尾的空格和点会去掉，去完为空时叫“未命名”。保存文件夹本身的路径太长、放不下任何名字时，不开始录音、不加入文件，并提示换一个路径短一些的文件夹。

“文档”文件夹被 OneDrive 或 iCloud 同步时，默认改存到用户主文件夹下的 `CourseScribe`，因为音频和文稿不能被自动上传。用户在设置里自己选的文件夹不受影响。

## 整理笔记（可选）

把一节课的校对稿整理成一份复习用的学习笔记，结构和用户在 Obsidian 里的整理笔记一致：核心宗旨、本课脉络、按讲课顺序分节、案例、类比、引述、提示词、结尾总结。

- 只在用户选择时生成。三种方式：任务完成后点“生成整理笔记”；把已有的 `.md` 拖进窗口或选中它；在设置里勾选“转录完自动生成整理笔记”（默认不勾）。
- 结果单独存成 `名称-整理笔记.md`，放在校对稿旁边。不修改 `.txt` 和 `.md`，不覆盖已有文件。
- 整理规则是一个文本文件（程序数据文件夹里的 `整理规则.txt`），在设置里点“打开整理规则…”打开，用户可以改，改完保存，从下一次整理开始生效。第一次打开时，程序把自带的通用规则复制一份过去；已经有的文件从不覆盖。以 `//` 开头的行是说明，不交给模型；其余文字原样交给模型（只统一换行、去掉开头和结尾的空行）。没有这个文件时用自带规则；文件里没有可用的规则（空的、只有说明或只有标点）时也用自带规则，并在完成提示里说明。规则文件读不了（编码认不出、被占用、没有权限、同名的是一个文件夹）时不整理，说明是哪个文件、怎么办，不悄悄换成自带规则；能认的编码和词表一样。交给模型的是整理规则、一小段固定的说明（不超过 128 个字）和校对稿去掉开头的 `# 标题`（第一个非空行是一级标题时）后的正文，正文除统一换行、去掉开头的 BOM 和首尾空行外一个字不改。
- 模型可以在设置里单独选，默认 `qwen3.5:9b`。和校对一样只用本机 Ollama。
- 程序负责以下各项，不依赖模型：
  - 开头信息（标题、日期、来源链接）由程序写。
  - 本课脉络的链接由程序按实际小节生成。
  - 引述和原文逐字核对，对不上的删掉。
  - 概念标签只保留原文里出现过的。
  - 完成后告诉用户删掉了几条（一条都没删就不说），并提醒笔记是初稿。
- 笔记是模型写的初稿，可能遗漏或概括不准，需要用户自己看一遍。
- 细节：
  - “生成整理笔记”按钮针对这次打开程序以后最近做完的一个录音或文件任务（整理笔记本身不算），任务做完后出现，正在处理别的任务时也可以点，会排在后面；鼠标停在按钮上会显示它整理的是哪一份校对稿。重新打开程序后按钮不在，这时和更早的课一样，把校对稿 `.md` 拖进来或点“选择文件”选中它。拖入 `.txt` 或 `*-整理笔记.md` 时说明不能用。一次拖入或选中多个文件时，音视频照常转录，校对稿整理笔记，不能用的各说明原因，原因一起显示，互不影响。
  - 日期取名称里的日期（如 `2026.10.30`、`2026-11-01`），没有就用任务建立的日期；不用“今天”，这样重做时内容不变。认 `年.月.日`、`年-月-日`、`年_月_日` 和 `X年X月X日`，年份在 2000–2099 之间；不认 8 位连写的数字。来源链接指向校对稿（`[[名称]]`），另留一行空的“来源：”给用户填课程地址；不写本机路径。
  - 本课脉络用 Obsidian 的 `[[#小节]]` 链接。
  - 笔记开头依次是：`# 名称`、空行、`日期：YYYY-MM-DD`、`校对稿：[[名称]]`、`来源：`。名称里有 Obsidian 链接不能用的字符（`#`、`|`、`^`、`[`、`]`）时，校对稿链接改用普通的 Markdown 链接。本课脉络放在“核心宗旨”之后，列出它后面的每个小节；没有“核心宗旨”时放在第一个小节之前。后面只有一个小节也写；后面没有小节时不写。小节名里的这几个字符换成对应的全角字符；同名的小节（比较时不分大小写和全角半角）合成一个：内容按出现的先后接在第一个后面，中间空一行，它们下面的小标题一起带过去；和名称或某个小标题相同的小节加“（2）”；改过名的“核心宗旨（2）”仍算核心宗旨。模型自己写的开头信息由程序去掉；模型写的一级标题只在它是第一个标题、并且是唯一的一级标题或者正好是 `# 名称` 时当作标题去掉；模型写的本课脉络连同它下面到下一个标题之前的内容一起去掉。模型的回答去掉这些后没有内容的，按下面“回答是空的”处理：自动请模型再写一次，还没有内容才算这次整理失败。
  - 引述只认“引述”小节里的内容（小节标题去掉其中的概念标签、序号、加粗、结尾的冒号和程序加的“（2）”后正好是“引述”，任何级别都算，包括它下面的小标题；代码块里的不算）。连续的 `>` 行算一条，其中每段话都要整段核对；只有署名的一段不算话，Obsidian 提示框的标题行是标签，不核对。其他行里用“”「」『』或英文双引号括起来的话，一行算一条，只核对引号里面的。小节里别的文字不是引述，原样保留。核对前去掉结尾的署名（最后一个 `——`、`—`、`--` 后面不超过 12 个字、不含逗号句号等标点和引号的部分，只去一次），然后只比文字和数字：不比标点、空格、换行、大小写和全角半角；“三”和“3”、繁体和简体算不同。原文是校对稿去掉第一行的 `# 标题`，跨行、跨段都算连着。带“……”的每一段都要按顺序在原文里。整条少于 4 个字（英文按字母数）的删掉（太短，核对不了）。一条里有一句对不上，整条删掉；引述小节删空了（包括一开始就是空的），连标题一起删，本课脉络按删完以后的小节生成。概念标签是行首或空格后面的 `#标签`（不认 `C#`、`#3`、链接、网址和代码里的 `#`），去掉 `_`、`-`、`/` 以后整个词要连着出现在原文里，否则只删这个标签；删完一行什么都不剩，或者这一行会因此变成标题、代码块、`>` 引述或开头信息，就删掉这一行；标题因此变成“本课脉络”的，按模型写的脉络连同下面的内容一起删。先删概念标签再核对引述，所以对不上的标签即使在被删的引述里也算一个。所有要删的行最后一起删，删完不留两段空行；删掉的地方前后都是 `>` 行时留一个空行，免得两条引述连成一条。完成提示分别说删了几条引述、几个概念标签（同一个标签出现几次算几个）。删完以后笔记没有内容的，按下面“核对后什么都不剩”处理：自动请模型再写一次，还不行才算这次整理失败。
  - 校对稿去掉第一行的 `# 标题` 后没有文字的，不调用模型，直接说明“这份校对稿是空的”，不整理。
  - 同一份校对稿已经在整理（包括排着队或等着 Ollama）时再点一次不重复整理，提示“已经在整理了”；上一次整理失败、还没点“忽略”的，再点就是重试那一次。整理完再点，新存一份 `名称-整理笔记 (2).md`（再点是 `(3)`，以此类推），即使内容和上一份一样；已有的笔记文件从不覆盖。程序在保存笔记前后被关掉，重新打开后接着做完，只留一份。
  - 课太长、一次放不进模型时，调用模型前就停下，说明这节课有多少字、这个模型一次最多能整理多少字；不悄悄截断。长度按一个字一个 token 保守估计，给模型的回答留出固定的长度，另给提示词留 256 的余量。整理规则本身就长到放不下任何课文时，说明是整理规则太长，请用户改短。拆成几段整理以后再做。
  - 模型的回答写到长度上限被截断、是空的，或者引述和概念核对后什么都不剩时，不保存半截或空的笔记，自动请模型再写一次（截断时提醒它写精简些，核对不上时提醒它逐字照抄）；还不行就算这次整理失败，并说明是哪一种情况。
  - 笔记模型没装时提示运行 `ollama pull 模型名` 或在设置里换成已有的模型，笔记任务等着，处理好后点“继续整理笔记”，继续整理笔记和重试都用设置里现在选的笔记模型。程序不自己下载。
  - Ollama 没启动、整理途中退出、太久没回应（目前一次整理最多等 30 分钟）或暂时出错时，笔记任务等着，说明校对稿已保存、没有变，处理好后点“继续整理笔记”，继续整理笔记和重试都用设置里现在选的笔记模型。暂时出错会先自动再试一次。
  - 模型写好的回答先存在任务的工作文件里。程序被关掉或保存笔记失败后再继续，不用再等模型重写；只有校对稿正文、整理规则、笔记模型或上下文长度变了才重新调用模型（只是换了换行、编码或名称不算变）。
  - 校对稿被移走、被占用、编码认不出（和文字稿一样，只认 UTF-8（带不带 BOM 都行）和带 BOM 的 UTF-16）、或者去掉标题后没有文字时，不整理，说明是哪个文件、怎么办，可以重试。笔记保存不了（磁盘满、文件夹是只读的）时说明原因，模型写好的内容留着，处理好后重试不用再等模型。笔记文件的路径或名字会超过系统的长度限制（同上）时不整理，请用户把校对稿挪到路径短一些的文件夹或改短名字（开始前就检查；开始后旁边才多出同名笔记、编号后的名字太长的，模型写好的内容留着，处理好后重试不用再等模型）。点“忽略”时，程序删掉这次整理留下的工作文件（里面有模型写的内容）。
  - 自动生成在校对稿写好后开始；校对在等待时笔记跟着等，校对继续做完后再开始。自动生成的笔记排在队尾，已经排着的转录先做。设置里的勾选和笔记模型从下一个做完的任务起生效。自动生成开始不了（校对稿刚被移走、笔记路径会太长、程序自己的数据文件夹写不进等）时，在“完成”提示下面另起一行说明原因，校对稿不受影响。校对稿刚写好、笔记任务还没记下时程序被关掉，下次打开不会自动补做，可以手动生成整理笔记。
  - 笔记和转录、校对排同一个队，同一时间只占一个模型：笔记模型用完（不论成功还是失败）马上让 Ollama 把它从显存里卸下；笔记失败不影响已经完成的 `.txt` 和 `.md`，可以重试或忽略。

## 硬规则

- **隐私：** 音频和文稿不离开本机。只有下载模型时联网，程序运行时不上传任何内容，也没有使用统计。
- **模型下载：** 程序不会静默下载大模型，下载前必须说明大小并得到同意。
- **平台：** Windows 和 Mac（Apple 芯片）都是正式平台。系统相关代码必须隔离，其他代码不能直接判断操作系统。
- **公开：** 以后会公开。仓库内容始终按公开标准管理：不放密钥、本机路径、私人录音或讲课内容。测试素材必须是自己生成或有权公开的。
- **路径：** 程序默认位置来自系统目录，不写死任何人的电脑路径。

## 怎样算做完

Jeremy 亲手验收，全部通过才算第一版完成：

1. 点开始、看课、点停止，全程不用再点别的，也不用选模型或参数。
2. 录音时电脑正常外放，不用改声音设置，Mac 只需首次授权。
3. 一节 1 小时的课，停止后自动生成 `.txt` 和 `.md`，无需人工盯着。
4. `.md` 能直接阅读，内容没有被总结或删减（语气词、口头禅和重复除外），最多只需修个别错字。
5. 强制关闭程序后，录音还在，并能继续完成转录。
6. 选择或拖入一个本地音视频文件后，无需其他操作，自动生成 `.txt` 和 `.md`。
7. 设置里能切换转录模型和校对模型，切换后下一个任务生效。

以上在 Windows 和 Mac 上都要通过。

## 给别人用的方式

- 公开时提供 Windows 和 Mac 安装包，同时公开源码。
- 安装包不做付费签名，Mac 用户首次打开需要手动放行。
- 模型不打进安装包，首次使用时提示下载。
- 校对依赖用户自己安装 Ollama，安装引导放到公开前的阶段做。

## 第一版不做

- 边录边显示文字。
- 录麦克风。
- 把总结、要点写进 `.md`，课后作业（旧项目的“深度排版”）。可选的整理笔记见上文，单独成文件。
- 云端转录或云端校对。
- 专门的词表编辑界面（第一版用文本文件编辑词表）。
- 正式发布和自动更新（第一版只演练打包，不公开发布）。
